I just finished OpenAI's Consultative Solutions Practitioner program, and I build on Azure. Here is the chain I now run every early AI opportunity through:

Workflow problem → use case → value hypothesis → solution route → next step.

Every stalled AI deal I've seen skips a link. The demo comes before the use case. The ROI number comes before the baseline. The product name comes before the workflow.

The one-sentence test for a use case:
"At [step], [who] uses AI to [produce what] for [work item], while [human role] reviews or decides, so [outcome] improves."

If you can't fill all five parts, you've found the real problem.

## 3. LinkedIn post B (the contrarian take)

Saved time is not saved money.

Hours saved are capacity. They only become savings when they turn into avoided hiring, a real cost cut or other measurable value.

So I follow one rule in pre-sales: no baseline, no claim.

On an insurance document-review build, I'm timing a complete customer file today, before anything runs. Until that number exists, I say "capacity", not "savings".

A CFO can forgive an unknown. They rarely forgive a number you can't defend.

## 4. LinkedIn post C (the carousel caption)

One ask. Five projects.

"AI for insurance documents" is really five projects with five different risk levels:

1. Missing documents: low risk, start here
2. KYC gaps: a person confirms
3. Fraud signals: AI flags, a person decides
4. Cross-sell: needs clean data first
5. Profitability: needs today's numbers

Start with the lowest risk, the easiest to measure. Swipe for the seven stages I use to get from "we need AI" to a credible next step.
